# 은수: 학습 언어와 형태소 경계가 한국어 토큰 수에 미치는 영향

## 이전 탐구와 연결

이전 탐구에서 한국어 입력이 영어 입력보다 토큰을 많이 사용했다는 관찰에서 출발한다. 사용자는 입력 프롬프트의 토큰량 확인 도구를 ‘GPT-5.6 토크나이저 툴이었던 것 같다’고 기억한다. 정확한 도구 URL, 선택한 모델·인코딩, 입력 문장, 원래 수치는 확인되지 않았다. 따라서 이전 결과를 재현했다고 주장하거나 특정 GPT 인코딩으로 임의 대체하지 않는다. 당시 도구의 주소나 기록을 확보하면 별도의 관찰 기준으로 추가한다.

OpenAI의 [공식 토큰 확인 도구](https://platform.openai.com/tokenizer)는 이전 도구를 확인할 때 참고할 후보이지, 사용자가 쓴 도구라는 확정 근거가 아니다.

## 연구 문제

‘영어의 분리 방식을 한국어에 적용’한다는 말을 이 구현에서는 **동일한 ByteLevel BPE 학습 방법에 한국어 학습 자료를 넣는 실험**으로 정의했다. BPE는 영어에만 적용되는 방법이 아니다. 단어를 공백으로만 나누는 방법과도 다르다. 실제 GPT와는 정규식·어휘·학습 자료·특수 토큰 등이 다르므로 영어 학습 조건을 ‘GPT’라고 부르지 않는다.

질문은 다음과 같다.

1. 같은 어휘 목표와 비슷한 UTF-8 학습 바이트 예산에서 학습 언어를 바꾸면 한국어 평가 문장의 토큰 수가 어떻게 달라지는가?
2. 한국어 학습 자료가 같을 때 원문 형태소 경계를 추가하면 토큰 수와 어휘 구성이 어떻게 달라지는가?
3. 모든 조건에서 공백·이모지·낯선 문자를 포함한 원문이 정확히 복원되는가?

한국어 자료로 학습하면 한국어 조각이 어휘에 더 많이 배정될 것이라는 가설이다. 형태소 경계의 효과는 증가와 감소 모두 가능하므로 측정한다. 토큰 수 감소와 대화 성능 향상은 별도 가설이다.

## 조건과 통제

| 조건 | 학습 언어 | 형태소 경계 |
|---|---|---|
| english_bpe | 영어 | 추가하지 않음 |
| korean_bpe | 한국어 | 추가하지 않음 |
| korean_morph_bpe | 한국어 | Kiwi의 원문 시작·끝 위치로 먼저 분할 |

모두 ByteLevel BPE, 초기 바이트 알파벳 256개, 최소 빈도 1, 정규화 없음, 특수 토큰 없음, 자동 접두 공백 없음이다. 학습량은 원문 앞부분의 UTF-8 바이트 상한으로 제한한다. 경계에서 잘린 문자의 마지막 바이트는 제외하며 실제 바이트 수를 기록한다. 짧은 자료를 반복해서 예산을 채우지 않는다. 실제 어휘 수가 목표에 도달하지 못하면 경고하며 동일 어휘 크기 비교로 확정하지 않는다.

형태소 조건은 원형으로 바꾸지 않고 **원문의 문자 범위를 자른다**. Kiwi가 제시한 겹치는 형태소의 시작·끝 위치도 분할 경계가 되므로 언어학적 정답 분할이라고 단정할 수 없다. 학습과 평가에 같은 규칙을 적용하며, 영어 평가에도 같은 Kiwi 경계 규칙을 적용한다. 저장된 `tokenizer_json`만으로는 외부 경계 처리가 복원되지 않으므로 `morphology_boundaries` 설정과 `research_tokenizer.encode`를 함께 사용한다.

평가 입력은 학습 입력과 별도로 받는다. 평가 문장이 학습 자료의 부분 문자열이면 거부한다. 의미상 유사 문장이나 표현의 중복까지 자동 검증하는 것은 아니다. 비교 대상 번역의 의미 동등성은 사람이 검토해야 한다. 토큰 ID는 각 어휘 내부에서만 의미가 있으며 조건 간 같은 숫자가 같은 단어라는 뜻은 아니다. 출력 기호는 ByteLevel의 바이트 표시 기호여서 독립적인 한글 글자가 아닐 수 있다.

## 예비 실행 결과

`pilot_corpus.json`은 구현 확인용으로 직접 작성한 소규모 자료다. 기존 탐구 자료나 대표성이 검증된 외부 말뭉치가 아니며 번역 검수도 필요하다. 목표 어휘 수 512, 언어별 학습 바이트 상한 1,000, 평가 6문장 쌍으로 실행했다. 정확한 실제 학습량, 라이브러리 버전, 입력 해시, 학습한 토크나이저, 문장별 ID는 `results/pilot.json`에 저장한다.

| 조건 | 실제 어휘 수 | 한국어 토큰 합 | 영어 토큰 합 | 한국어/영어 합계 비 |
|---|---:|---:|---:|---:|
| 영어 학습 BPE | 512 | 370 | 160 | 2.313 |
| 한국어 학습 BPE | 512 | 187 | 334 | 0.560 |
| 한국어 원문 형태소 경계 BPE | 512 | 183 | 334 | 0.548 |

이 자료에서는 한국어 학습 BPE의 한국어 토큰 수가 영어 학습 BPE보다 약 49.5% 적었다. 형태소 경계 추가 조건은 한국어 학습 BPE보다 약 2.1% 적었다. 모든 평가 행에서 원문 복원을 확인했다. 영어 토큰 수는 한국어 학습 조건에서 증가했다. 따라서 합계 비가 낮아진 사실만으로 전체 효율이 좋아졌다고 판단하면 안 된다. 이 수치는 작은 인공 자료의 예비 결과이며 GPT 대비 개선율이나 일반 한국어의 개선율이 아니다.

## 보고서에 포함할 한계와 후속 실험

- 바이트 예산이 같아도 한국어·영어의 문자 수, 포함된 문장 수, 의미량은 다르다. 앞부분 절단 때문에 서로 번역인 학습 문장도 동일 범위로 사용되지 않는다. 언어만의 순수한 인과 효과로 해석할 수 없다.
- 한 번의 작은 학습·평가 결과다. 대표 말뭉치, 장르별 독립 평가, 여러 학습 부분집합, 복수 어휘 예산으로 반복하고 문장 쌍별 분포와 변동을 제시해야 한다. 문장 수·의미 단위 예산을 맞춘 추가 실험도 필요하다.
- 현재 측정은 본문 토큰 수·문자당 토큰 수·원문 복원이다. 추론 시간, 메모리, 과금, 의미 이해, 답변 정확도는 측정하지 않았다. 시스템 지침이나 채팅 템플릿도 포함하지 않는다.
- 현재 채팅은 기존 Qwen3 모델이다. 연구용 어휘로 입력 ID만 바꾸면 임베딩과 출력층의 의미가 맞지 않는다. 실제 ‘은수 한국어 모델’의 성능을 평가하려면 해당 토크나이저로 언어 모델을 학습하거나 임베딩·출력층을 조정하고 재학습해야 한다. 한국어 프롬프트 설정은 이 학습을 대신하지 않는다.

## 재현

```sh
.venv/bin/python scripts/run_research.py
.venv/bin/python -m unittest discover -s tests
```

생성 API와 사전 API를 호출하지 않는다. 기본 출력은 `research/results/pilot.json`, `research/results/pilot.csv`이다. JSON에는 실제 사용한 학습 원문도 포함되므로 공유할 자료를 직접 검토한다. 이 문서와 스크립트는 이전 예비 실험의 참고 자료로 보관한다. 앱에는 별도 탐구 탭을 제공하지 않으며, 토큰 확인은 기존 토크나이저 실험실에서 진행한다. 새로 학습한 파일은 병합 동률 처리나 라이브러리 차이로 바뀔 수 있으므로 재현 시 저장된 토크나이저 파일과 버전도 함께 보관한다.

- [Sennrich 외, 2016, Neural Machine Translation of Rare Words with Subword Units](https://aclanthology.org/P16-1162/): 서브워드 단위 BPE를 다룬 원 논문. 이 예비 실험의 성능을 입증하는 자료는 아니다.
- [OpenAI 공식 토큰 확인 도구](https://platform.openai.com/tokenizer): 이전 실험의 도구·설정을 확인하기 위한 참고 링크.
